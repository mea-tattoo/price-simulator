# 料金正本と確定後の反映

## 構成

- 正本: `gakkii415/tattoo-pricing-core` の料金設定・共通計算関数。
- このリポジトリ: 画面と、正本から機械的に取り込んだ `vendor/pricing.js`。
- `pricing-lock.json`: 利用中の正本リポジトリ・コミットSHA・料金版・ハッシュ。
- アーティスト用と顧客用で同じ関数を使用。顧客用では従来どおり余白補正を使わない。
- 起動時のネット経由参照は不要。取得失敗で料金が変わることはなく、取り込み済みの版で動く。

## 改定の手順

1. 正本の検討用ブランチで案を作り、旧料金との比較とテストを行う。この時点で本サイトは変化しない。
2. ユーザーが「この案で確定して反映して」と指示した内容を正本mainへ取り込む。
3. AIはGitHubプラグインで `.pricing-release.json` に `repository` と `commit`（そのmainの完全な40文字SHA）を書き込み、mainへ反映する。これだけで `Apply confirmed pricing` が起動する。ブラウザ認証やAIによる料金コードの書き換えは不要。Actionsの手動実行も使用可能。
4. 固定処理が正本を取得・ビルド・検査し、共通JSとロックを更新する。料金結果をAIがHTMLへ転記する工程はない。
5. 両画面の接続を検査した後、mainへコミットし、既存のブランチ式Pages公開を要求する。
6. 公開された両HTML・共通JS・ロックの内容が今回の成果物と一致するまで確認する。失敗時は完了扱いにせず、失敗箇所から修復する。

特別なクロスリポジトリ書き込みトークンは不要。正本を読み、このリポジトリ自身の `GITHUB_TOKEN` で反映する。正本はすでに公開中の料金コードだけを含む公開リポジトリを想定する。

大幅な計算方式変更でも `calculate` 等のAPI v1を保てば画面は継続利用できる。新しい入力項目や破壊的な返却形式変更が必要なら、先に画面側を対応させる。API不一致は自動処理が拒否する。

## 初回移行の状態

`bootstrapPending: true` のロックは作成準備中を意味する。新規正本リポジトリ作成後、正本をテスト・ビルドし、そのコミットから `node scripts/sync-pricing.cjs <checkout> <sha>` を実行して解除する。解除前は本番マージしない。

旧開発用 `gakkii415/tattoo-price-simulator-dev` は独立した過去の試作で、現行正本の配布先ではない。そこにある旧料金を現行料金として扱わない。シート紐付けGASの本体は未取得のため配布対象に含めていない。

## 失敗・差し戻し

更新処理は途中で失敗すれば停止し、成功と報告しない。コミット後のPages公開に失敗した場合は同じSHAで再実行して公開を再要求する。前の料金へ戻す場合は正本mainで確定変更をrevertし、その新しいmain SHAを指定して同じ処理を行う。

同時のmain更新はgit pushの拒否または公開コミット照合で検出する。料金反映中は通常の本番マージを重ねない。GitHubの既存の保護ルールに拒否された場合はルールを迂回しない。
